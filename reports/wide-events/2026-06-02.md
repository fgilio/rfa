## Findings

### [WARNING] Canonical context records raw exception message under `rfa.error`

- **File:** `resources/views/pages/⚡review-page.blade.php:513`
- **Rule:** Privacy ("Do not log raw exception messages unless they are known safe or redacted") and anti-pattern catalog in `.claude/skills/wide-events/SKILL.md` ("`Context::add('rfa.error', $e->getMessage());`")
- **Evidence:** The `softRefresh` catch block adds `rfa.error` with `$e->getMessage()` to the canonical context for `review.refreshed`. The standard lists this exact call shape as an anti-pattern.
- **Impact:** Throwable messages leak absolute paths, SQL fragments, stderr, or other unredacted content into the canonical event that lands in the local log file.
- **Suggested fix:** Drop the `rfa.error` Context add. Keep `rfa.error_class` and add a stable `rfa.reason` code (for example `refresh_failed`). Reserve free-form text for diagnostic `Log::error` payloads when truly needed.

### [WARNING] Updater info events skip `rfa.duration_ms`

- **File:** `app/Providers/NativeAppServiceProvider.php:92-96`, `app/Providers/NativeAppServiceProvider.php:127-131`
- **Rule:** Canonical Info Events ("Canonical events include `rfa.duration_ms`. There are no duration exemptions. Near-instant operations should still record the measured duration.")
- **Evidence:** The `UpdateAvailable` and `UpdateDownloaded` listeners flush context, add `rfa.update_version` and `rfa.outcome = completed`, then `Log::info('updater.available')` and `Log::info('updater.downloaded')` without measuring a duration.
- **Impact:** Canonical events lose a required field. Future regressions in update callback latency cannot be debugged without re-reading code.
- **Suggested fix:** Capture `microtime(true)` at the top of the listener callback and add `rfa.duration_ms` before the `Log::info` call, even though the value will normally be tiny.

### [WARNING] Updater error path uses `Log::error` as the canonical event

- **File:** `app/Providers/NativeAppServiceProvider.php:147-161`
- **Rule:** Errors And Criticals ("`Log::error()` is diagnostic. It never replaces the owner canonical info event."). Privacy ("Do not log raw exception messages unless they are known safe or redacted... raw stderr").
- **Evidence:** The `UpdateError` listener flushes context, sets `rfa.outcome = error`, then emits only `Log::error('updater.failed', ['message' => $event->message, 'stack' => $event->stack])`. No `Log::info('updater.failed')` is emitted, so the listener owns no canonical info event for the failed updater operation. The payload includes the raw `message` and `stack` from the NativePHP autoupdater event.
- **Impact:** Querying canonical events for updater outcomes will not find the failed cases. Raw `message` and `stack` may include absolute paths, URLs, or noisy autoupdater output.
- **Suggested fix:** Keep the diagnostic `Log::error` if extra detail is wanted, but also emit `Log::info('updater.failed')` so the canonical event exists with `rfa.outcome = error`, `rfa.duration_ms`, and `rfa.reason = updater_error`. Replace the raw `message`/`stack` payload with a sanitized summary or a short hash.

### [WARNING] Raw `stderr` in git warning payloads

- **File:** `app/Actions/LoadFileDiffAction.php:44-48`, `app/Actions/GetProjectStatusAction.php:27-31`
- **Rule:** Warnings ("avoid raw file contents, raw stderr, secrets, and avoidable absolute paths"). The standard lists `Log::warning('Git diff failed', ['stderr' => $e->stderr])` as an anti-pattern.
- **Evidence:** Both warnings emit `'stderr' => $e->stderr` directly from `GitCommandException`. The good example in the standard uses `stderr_summary` after sanitization.
- **Impact:** Git stderr commonly contains absolute repo paths, ref names with branch metadata, or remote URLs. Logs become noisier and leak filesystem layout.
- **Suggested fix:** Add a `stderr_summary` helper that truncates and strips absolute paths, then pass that instead of `$e->stderr`. Same shape across both actions so the field stays queryable.

### [WARNING] Raw exception messages in many service and action warnings

- **File:** `app/Actions/EnsureRfaGitExcludeAction.php:52-56` and `:76-80`, `app/Actions/OpenProjectFromPathAction.php:36-40`, `app/Actions/ResolveBranchBaseAction.php:82-88`, `app/Services/GitMetadataService.php:25-29, :150-156, :173-178, :201-206, :225-230, :270-275, :344-348`
- **Rule:** Warnings ("avoid raw file contents, raw stderr, secrets, and avoidable absolute paths") and Privacy ("Do not log raw exception messages unless they are known safe or redacted").
- **Evidence:** Each warning includes `'error' => $e->getMessage()` where `$e` is a generic `Throwable` or `GitCommandException`. Twelve call sites follow the same shape.
- **Impact:** `Throwable::getMessage()` may contain absolute paths, ref names, or other implementation detail. The stable `reason` field already conveys the failure class, so the raw message adds noise more than diagnostic value.
- **Suggested fix:** Replace each `'error' => $e->getMessage()` with `'error_class' => $e::class` and rely on `reason` for the stable code. If a sanitized excerpt is genuinely useful, route it through a helper that strips absolute paths.

### [WARNING] Default channel is unbounded `single` at `debug` level

- **File:** `config/logging.php:21`, `config/logging.php:53-66`, `.env:18-21`
- **Rule:** Storage ("**[Review SHOULD]** The app default channel resolves to local daily files with bounded retention and `info` level"). The recommended block uses `daily` with `days: 7` and `level: info`.
- **Evidence:** Resolved default channel is `stack`, which fans out to `LOG_STACK=single`. The `single` channel writes to one ever-growing `laravel.log` with no rotation. `LOG_LEVEL=debug` is committed in `.env` and `.env.example`.
- **Impact:** Logs accumulate without bound on installed machines. `debug` level invites future noise even though the arch test forbids `Log::debug` in production code, because framework and vendor code can still emit debug records.
- **Suggested fix:** Set `LOG_CHANNEL=daily` (or change `LOG_STACK=daily`) and `LOG_LEVEL=info` in `.env` and `.env.example`. Add `'days' => 7` to the daily channel, mirroring the standard's example. Remote channel definitions can stay in `config/logging.php` as long as they are not active in the default stack, and the arch test already enforces that.

### [INFO] No canonical info event for the context comment add operation

- **File:** `resources/views/pages/⚡context-page.blade.php:236-275`
- **Rule:** Logging Ownership and Outcome Semantics ("Do not warn for every normal rejected input. Use the owner canonical event with `rfa.outcome = rejected`.")
- **Evidence:** `createComment` is the Livewire owner for a user-facing comment write. It delegates to `ContextCommentWorkflowAction` and only emits a `Log::warning('context.comment.rejected', ...)` on the rejected branch. Successful adds emit no canonical info event.
- **Impact:** "What happened to this comment write?" cannot be answered without reading source. Rejection rate, success rate, and write duration are invisible. The current shape also pushes a normal rejected input into the warning channel.
- **Suggested fix:** Wrap the `try`/`catch` in the canonical pattern (flush, start timer, finally emit `context.comment.added`) with `rfa.outcome = completed | rejected`, `rfa.reason` for the rejection branch, and useful counts (`rfa.file_id`, `rfa.is_draft`, `rfa.body_length`). Demote the warning to be emitted only on truly unexpected reject reasons, or drop it if the canonical event covers it.

### [INFO] Absolute `repo` paths in git service warnings

- **File:** `app/Services/GitMetadataService.php:25-29, :150-156, :173-178, :201-206, :225-230, :270-275, :344-348`, `app/Actions/EnsureRfaGitExcludeAction.php:52-56` and `:76-80`, `app/Actions/ResolveBranchBaseAction.php:82-88`, `app/Actions/GetProjectStatusAction.php:27-31`
- **Rule:** Privacy ("Prefer project slugs, relative file paths, hashes, counts, booleans, and stable reason codes. Absolute paths are allowed in warning payloads only when no project context can resolve a relative path or when the path itself is the failed input being diagnosed.")
- **Evidence:** Most service warnings include `'repo' => $repoPath` or `'repoPath' => $repoPath`. The path is generally the project's absolute working directory rather than a slug.
- **Impact:** Warning streams reveal home directory layout. When correlating with the canonical `review.refreshed` context (which uses `rfa.project_id` and `rfa.project_slug`), the slug would be a stronger queryable key.
- **Suggested fix:** Either rely on the owner-set `rfa.project_slug` Context field for correlation and drop `repo` from warning payloads, or thread an optional `projectSlug` into the service methods that need it. The action callers (which know the project) can prefer the slug.

## Clean Areas

- `review.refreshed` ownership is clear. The Livewire `softRefresh` method is the sole logging owner. It flushes context first, measures duration, sets `rfa.outcome` in `finally`, and emits a single canonical event. Child services on this path only emit warnings.
- Warning payloads consistently include a stable `reason` literal that matches the SKILL's reason-code style.
- Event names are all lowercase dot-separated literals with two to four segments, in line with C3.
- `Context::add` keys all use the `rfa.` prefix, in line with C4.
- The default channel resolution does not pull in `slack`, `papertrail`, `syslog`, or `errorlog`, so C8 holds at runtime.
- No `Log::debug` calls in production, in line with C1.

## Residual Risks

- The audit looked at static call shapes. It did not simulate runtime to confirm that every `Context::add` field is observed exactly once on the canonical event, or that child warnings actually inherit the owner context in NativePHP's long-lived process.
- `GitCommandException::stderr` content was not sampled at runtime. Some sites may already produce safe summaries.
- The release path under `app/Console/`, `app/Listeners/`, and `app/Events/` was not exhaustively walked beyond the inventory results. Only the files touched by the `Log::` / `Context::` ripgrep were re-read in full.
- Browser, console, and queue paths outside `app/` and `resources/views/` (for example `bootstrap/` and `routes/`) were not part of the scoped inventory.
