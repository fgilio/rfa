## Findings

### [WARNING] Raw exception message stored on canonical event context

- **File:** `resources/views/pages/⚡review-page.blade.php:529`
- **Rule:** Privacy. Skill section "Privacy" and Agent check A9 forbid raw exception messages in canonical context.
- **Evidence:** In the `catch` block of `softRefresh()`, `Context::add('rfa.error', $e->getMessage())` attaches the raw `Throwable` message to the `review.refreshed` canonical event.
- **Impact:** Exception messages can carry absolute paths, SQL, stderr fragments, or user-provided strings. They land in `rfa.error` on every error-path canonical event and survive in daily log files.
- **Suggested fix:** Drop `rfa.error`. Keep `rfa.error_class` and add a stable `rfa.reason` code instead. If a sanitized message snippet is genuinely useful for debugging, redact and bound it before adding.

### [WARNING] Canonical updater events lack `rfa.duration_ms`

- **File:** `app/Providers/NativeAppServiceProvider.php:97,132,152`
- **Rule:** Mechanics > Canonical Info Events ("Canonical events include `rfa.duration_ms`. There are no duration exemptions.") and Agent check A6.
- **Evidence:** The `UpdateAvailable`, `UpdateDownloaded`, and `UpdateError` listeners emit `updater.available`, `updater.downloaded`, and `updater.failed` with no measured duration on the context. The listeners do not capture a `$startedAt`.
- **Impact:** The canonical event loses the duration field the rest of the standard depends on. Querying duration histograms or detecting slow update-channel paths is impossible.
- **Suggested fix:** Capture `microtime(true)` at the top of each listener callback, then add `rfa.duration_ms` before `Log::info()` (or `Log::error()` for the failed path). Listener callbacks are short so the measured value is small but the field is still required.

### [WARNING] `updater.failed` emits only `Log::error()` and skips the canonical info event

- **File:** `app/Providers/NativeAppServiceProvider.php:148-156`
- **Rule:** Mechanics > Errors And Criticals ("`Log::error()` never replaces the owner canonical info event.") and Agent check A11.
- **Evidence:** The `UpdateError` listener sets `rfa.outcome = error`, then calls only `Log::error('updater.failed', [...])`. There is no companion `Log::info('updater.failed')` from the owner.
- **Impact:** Successful update paths surface as canonical info events but the failure path does not. Outcome queries that filter to canonical info events miss every updater failure.
- **Suggested fix:** Emit a single canonical `Log::info('updater.failed')` after the context is populated. Drop the `Log::error()` unless a sanitized payload genuinely adds diagnostic detail beyond what context already carries.

### [WARNING] `updater.failed` payload includes raw message and stack

- **File:** `app/Providers/NativeAppServiceProvider.php:152-156`
- **Rule:** Privacy and Mechanics > Errors And Criticals ("Do not log raw exception messages unless they are known safe or redacted.").
- **Evidence:** `Log::error('updater.failed', ['reason' => 'updater_error', 'message' => $event->message, 'stack' => $event->stack])`. The `message` and `stack` come straight from the NativePHP updater event.
- **Impact:** Update errors often include URLs, absolute paths, or HTTP body fragments. The stack trace likely contains absolute file paths. None of this is sanitized.
- **Suggested fix:** Replace with a bounded `error_class` plus a sanitized `message_summary` (first line, length-capped) if a message is needed. Drop `stack` from the persisted payload.

### [WARNING] `git.diff.failed` warning passes raw stderr

- **File:** `app/Actions/LoadFileDiffAction.php:51-55`
- **Rule:** Mechanics > Warnings ("avoid raw file contents, raw stderr") and Agent check A9.
- **Evidence:** `Log::warning('git.diff.failed', ['reason' => 'diff_process_failed', 'path' => $path, 'stderr' => $e->stderr])`.
- **Impact:** Git stderr can echo absolute paths and file content fragments back to logs. The skill's worked example uses `stderr_summary` instead.
- **Suggested fix:** Replace `stderr` with a sanitized `stderr_summary` produced by a small helper that strips control characters and caps length. Drop any path content that the helper finds.

### [WARNING] `project.status.failed` warning passes raw stderr and absolute repo path

- **File:** `app/Actions/GetProjectStatusAction.php:27-31`
- **Rule:** Mechanics > Warnings and Privacy.
- **Evidence:** Payload contains `'repoPath' => $repoPath` and `'stderr' => $e->stderr`.
- **Impact:** Absolute repo path and raw stderr land in the daily log on every status failure. Project slug is the standard preferred substitute and is reachable from `$repoPath`.

### [WARNING] Git metadata service warnings consistently emit raw `$e->getMessage()` and absolute repo path

- **File:** `app/Services/GitMetadataService.php:26-30,151-157,174-179,202-207,226-231,271-276,345-349`
- **Rule:** Mechanics > Warnings, Privacy, Agent check A9.
- **Evidence:** Every git failure warning uses the same shape: `'repo' => $repoPath` plus `'error' => $e->getMessage()`. Examples include `git.excludes_file.resolve_failed`, `git.file_content.read_failed`, `git.ref.resolve_failed`, `git.commit_parents.read_failed`, `git.root_commit.check_failed`, `git.child_commit.read_failed`, and `git.commit_log.read_failed`.
- **Impact:** Repeated absolute paths and raw git error strings pollute the local log. Many of these warnings fire during normal navigation so the noise is sustained.
- **Suggested fix:** Add the project context (slug) to `Context::add` at the owner boundary or pass a `project_slug` parameter into the service. Replace `error` with `error_class` plus an optional sanitized summary.

### [INFO] Default log channel does not match the wide-events doctrine default

- **File:** `config/logging.php:21,53-74`
- **Rule:** Storage > Review SHOULD (default channel resolves to local daily files, bounded retention, `info` level).
- **Evidence:** Default channel is `stack`, the stack defaults to `single` (unbounded retention), and both `single` and `daily` default `LOG_LEVEL` to `debug` rather than `info`.
- **Impact:** Local retention is unbounded and the default level is noisier than intended. Remote channels (`slack`, `papertrail`, `syslog`, `errorlog`) are defined but not active in the resolved default stack, so the CI MUST rule still passes.
- **Suggested fix:** Set `LOG_CHANNEL` default to `daily` and `LOG_LEVEL` default to `info`, matching the doctrine snippet. The CI must rule on remote channels is unaffected by either change.

## Residual Risks

- This audit relies on static review. Runtime behavior under NativePHP's long-lived PHP process (context leakage between unrelated operations) is not exercised here. The skill warns that this is a concrete risk and the canonical pattern's `Context::flush()` at the owner is the only defense. The updater listeners do flush, but each new owner added in the future has to repeat the pattern.
- The skill requires a logging owner per externally meaningful operation. Several actions and services emit warnings but no owner has been identified for some flows (for example, `EnsureRfaGitExcludeAction` is invoked from project registration but the parent project-registration owner does not currently emit a canonical info event). A follow-up audit could enumerate owners systematically.
- Sanitization of `stderr` and exception messages would benefit from a shared helper rather than ad hoc per-call work. None is in place today.
- No verification was done that warning logs preserve the owner context across the renderer process boundary in production. Verifying this requires running a packaged build and inspecting a real log file.
