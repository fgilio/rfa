## Findings

### [WARNING] Updater canonical events are missing `rfa.duration_ms`

- **File:** `app/Providers/NativeAppServiceProvider.php:84-110` and `app/Providers/NativeAppServiceProvider.php:127-145`
- **Rule:** Wide-events skill "Canonical Info Events" and Agent check A6. `rfa.duration_ms` has no exemption, even for listener callbacks.
- **Evidence:** The `UpdateAvailable` and `UpdateDownloaded` listeners flush context, add `rfa.update_version` and `rfa.outcome = 'completed'`, then `Log::info('updater.available')` / `Log::info('updater.downloaded')`. No `microtime(true)` start, no `rfa.duration_ms` field.
- **Impact:** Operators cannot answer "how long did the updater callback take" from logs. Loses one of the two required canonical-event invariants.
- **Suggested fix:** Wrap each listener in a `try/finally` with a start time and emit `rfa.duration_ms` covering the callback. The skill states the listener owns its callback duration when there is no reliable upstream operation start time.

### [WARNING] Updater error path emits no canonical info event

- **File:** `app/Providers/NativeAppServiceProvider.php:147-161`
- **Rule:** Wide-events skill "Logging Ownership" and A11. The logging owner emits the canonical info event from `finally` even on error paths. `Log::error()` is diagnostic only.
- **Evidence:** The `UpdateError` listener flushes context, sets `rfa.outcome = 'error'` and `rfa.reason = 'updater_error'`, then calls `Log::error('updater.failed', [...])` with no corresponding `Log::info('updater.failed')` or `updater.checked` canonical event.
- **Impact:** The updater operation has no consistent canonical info event across success/error paths. Queries that filter by `rfa.outcome` will miss the failure case.
- **Suggested fix:** Emit a single canonical info event for the updater outcome (for example `updater.checked` or `updater.failed`) with `rfa.outcome`, `rfa.duration_ms`, and `rfa.reason`. Keep `Log::error()` only if extra diagnostic detail is genuinely needed beyond the canonical event.

### [WARNING] `updater.failed` payload includes raw error message and stack

- **File:** `app/Providers/NativeAppServiceProvider.php:151-155`
- **Rule:** Wide-events skill "Errors And Criticals" and Privacy. Do not log raw exception messages or stacks unless redacted.
- **Evidence:** Payload passes `'message' => $event->message` and `'stack' => $event->stack` straight from Electron's auto-updater error event.
- **Impact:** Auto-updater stack traces and error strings routinely include absolute filesystem paths, network URLs, and electron-bundle internals.
- **Suggested fix:** Replace with a stable reason code, an `error_class` if available, and a sanitized one-line summary. Hash or truncate any free-form text.

### [WARNING] `softRefresh` writes raw exception message into static context

- **File:** `resources/views/pages/⚡review-page.blade.php:520`
- **Rule:** Wide-events skill "Anti-Patterns" lists `Context::add('rfa.error', $e->getMessage())` explicitly.
- **Evidence:** Inside the `catch (\Throwable $e)` branch of `softRefresh()`, `Context::add('rfa.error', $e->getMessage())` is called before re-throw.
- **Impact:** Raw exception messages can carry absolute paths, SQL fragments, or user-visible data and leak onto the canonical `review.refreshed` event.
- **Suggested fix:** Drop the `rfa.error` field. Keep `rfa.error_class` and add an `rfa.reason` with a stable code. Free-form text belongs in a redacted summary or out of logs entirely.

### [WARNING] Warning payloads pass raw `stderr` instead of a sanitized summary

- **File:** `app/Actions/GetProjectStatusAction.php:27-31`, `app/Actions/LoadFileDiffAction.php:51-55`
- **Rule:** Wide-events skill "Warnings". Example shows `'stderr_summary' => $sanitizedSummary`, not raw stderr.
- **Evidence:** Both call sites pass `'stderr' => $e->stderr` from a `GitCommandException`.
- **Impact:** Git stderr can include absolute paths, ref names, hostnames in URL-form remotes, and other free-form text the user did not opt into logging.
- **Suggested fix:** Add a small `sanitizeStderr()` helper that trims, truncates to one line, and drops absolute paths. Pass it as `stderr_summary`.

### [WARNING] Many warning payloads embed raw `$e->getMessage()` as `error`

- **File:** `app/Actions/EnsureRfaGitExcludeAction.php:52-56`, `:76-80`; `app/Actions/OpenProjectFromPathAction.php:36-40`; `app/Actions/ResolveBranchBaseAction.php:82-88`; `app/Services/SyntaxHighlightService.php:247-251`, `:555-558`; `app/Services/GitMetadataService.php:26-30`, `:151-157`, `:174-179`, `:202-207`, `:226-231`, `:271-276`, `:345-349`
- **Rule:** Wide-events skill "Errors And Criticals" and Privacy. Raw exception messages are presumed unsafe unless known safe or redacted.
- **Evidence:** Each warning payload carries `'error' => $e->getMessage()` alongside the stable `reason` field.
- **Impact:** The reason code already encodes the failure semantics. The raw message adds little diagnostic value while increasing the chance of leaking absolute paths or user data into the local log.
- **Suggested fix:** Replace with `'error_class' => $e::class` plus an optional truncated summary. Drop `getMessage()` unless the message is constructed by RFA from sanitized inputs.

### [WARNING] Default channel `single` has unbounded local retention

- **File:** `config/logging.php:61-66`, `.env` (`LOG_STACK=single`)
- **Rule:** Wide-events skill Storage `[Review SHOULD]`. The recommended pattern is a `daily` channel with bounded retention.
- **Evidence:** `LOG_CHANNEL=stack` and `LOG_STACK=single` route the default stack to the `single` driver, which writes to `storage/logs/laravel.log` with no rotation. The `daily` channel exists with `LOG_DAILY_DAYS=14` but is not in the default stack.
- **Impact:** A packaged install grows its log file forever. The skill explicitly flags unbounded local retention.
- **Suggested fix:** Either point `LOG_STACK` at `daily`, or replace `single` in the default stack with `daily`. Set `days` to 7 per the skill's example.

### [WARNING] Default log level is `debug` in env defaults

- **File:** `.env` (`LOG_LEVEL=debug`), `config/logging.php:64`, `:71`
- **Rule:** Wide-events skill Storage `[Review SHOULD]`. Recommended default is `info`.
- **Evidence:** Both `single` and `daily` channels resolve `'level' => env('LOG_LEVEL', 'debug')`. CI rule C1 forbids `Log::debug()` in production code, so the level is effectively meaningless for application logs today, but the env default still admits framework debug noise.
- **Impact:** Framework or vendor debug output is admitted into the active channel and inflates log size.
- **Suggested fix:** Set the default to `info` in both channel definitions, or set `LOG_LEVEL=info` in `.env` and `.env.example`.

### [INFO] Several warning payloads carry absolute `repo` paths

- **File:** `app/Actions/EnsureRfaGitExcludeAction.php:54`, `:78`; `app/Actions/ResolveBranchBaseAction.php:85`; `app/Services/GitMetadataService.php:28`, `:153`, `:176`, `:204`, `:228`, `:273`, `:346`
- **Rule:** Wide-events skill Privacy. Absolute paths are allowed in warning payloads only when the path is the failed input being diagnosed.
- **Evidence:** Warnings carry `'repo' => $repoPath` where `$repoPath` is the absolute repo root. Action/service entry points usually already know a project slug or hash.
- **Impact:** Warnings already correlate with the owner canonical event by inheriting context. The absolute path adds little once `rfa.project_slug` is on the owner event.
- **Suggested fix:** When called from an action that has a `Project`, drop `repo` from the payload and let owner context carry `rfa.project_slug`. Where no slug is in scope, hash the path or keep the absolute value but mark it as the failed input.

## Clean Areas

- `review.refreshed` (`resources/views/pages/⚡review-page.blade.php:493-554`) is a textbook canonical event: `Context::flush()`, `microtime(true)` start, try/finally, `rfa.outcome` set on both branches, `rfa.duration_ms`, rich IDs/counts/booleans, and clear past-tense event name.
- Every logging owner calls `Context::flush()` before adding fields. No child action or service adds non-owner context fields that would persist between operations.
- All static `Context::add()` keys use the `rfa.` prefix.
- Every `Log::warning()` payload carries a stable `reason` code (arch test passes).
- Event names are lowercase dot-separated past-tense literals throughout.
- No remote log channels (slack, papertrail, syslog, errorlog, remote monolog handlers) are reachable from the resolved default stack.
- `RuntimeDiagnosticsService::breadcrumb()` writes JSONL to its own file, so the `review.refreshed` owner does not double-emit through `Log::*`.

## Residual Risks

- Agent review is bounded. Some `$e->getMessage()` payloads may already be safe based on the throwing site, but proving that statically is out of scope. Findings 5 and 6 are conservatively flagged.
- The arch test enforces `reason` on warnings but not its vocabulary. Reason codes are not cross-checked for stability across releases.
- This audit did not run `composer test`, `composer test:lint`, or `composer test:types` and so cannot speak to broader regressions.
- The `LOG_LEVEL=debug` finding assumes packaged installs inherit the `.env` defaults. If shipping config overrides this in `nativephp` build steps, the finding is moot.
